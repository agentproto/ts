### Evidence paragraphs

**1/1b — Anthropic.** The official rate-limits page (https://platform.claude.com/docs/en/api/rate-limits) lists, verbatim in its Response headers table: `anthropic-ratelimit-requests-limit`, `anthropic-ratelimit-requests-remaining`, `anthropic-ratelimit-requests-reset`, `anthropic-ratelimit-tokens-limit`, `anthropic-ratelimit-tokens-remaining`, `anthropic-ratelimit-tokens-reset`, and the `-input-tokens-` and `-output-tokens-` variants, plus the `anthropic-priority-input-tokens-remaining` / `anthropic-priority-output-tokens-remaining` family "(Priority Tier only)". **No `anthropic-ratelimit-unified-*` header appears anywhere on this page, and no `7d`, weekly, or per-window (5h) upstream limit is documented anywhere on the page.** A targeted web search across `platform.claude.com` / `docs.claude.com` found only these documented families plus the organization-level **Rate Limits API** (`GET /v1/organizations/rate_limits`, an admin-API page at https://platform.claude.com/docs/en/manage-claude/rate-limits-api). Conclusion: the 5h/7d `unified` headers — including any hypothetical weekly Sonnet window — are **undocumented** on the official site; the code's parsing of them is a could-not-verify dependency and any additional window id (e.g. `7d_sonnet`) cannot be verified from official sources.

**2/2b — OpenRouter.** The limits page documents "To check the rate limit or credits left on an API key, make a GET request to `https://openrouter.ai/api/v1/key`" and gives the full response shape, including `limit_remaining: number | null // Remaining credits for the key, or null if unlimited` — which exactly confirms the codebase's null = cap-less semantics — plus newer fields worth mapping (`budgets[]`, `effective_budget` with `remaining_usd`/`resets_at`, `free_model_daily_requests`, `usage_daily/weekly/monthly`). The credits page for `GET /api/v1/credits` states "Get total credits purchased and used for the authenticated user. [Management key](/docs/guides/overview/auth/management-api-keys) required" and returns `data.total_credits` / `data.total_usage` (403 otherwise). Note: successful inference responses do **not** carry `X-RateLimit-*` headers; those only appear on platform 429 errors.

**3 — Moonshot/Kimi.** https://platform.kimi.ai/docs/api/balance documents exactly `GET https://api.moonshot.ai/v1/users/me/balance` with Bearer auth and response fields `data.available_balance` ("The available balance (unit: USD)... When it is less than or equal to 0, the user cannot call the inference API"), `data.voucher_balance`, `data.cash_balance`, wrapped in `code`/`status`/`scode`. This confirms the existing code mapping `data.available_balance`.

**4 — Codex.** In the official repo (shallow-cloned at commit of 2026-10-18), `codex-rs/codex-api/src/rate_limits.rs` parses the default `x-codex-*` header family via `parse_all_rate_limits(&stream_response.headers)` and an SSE event: `RateLimitEvent { type, plan_type, rate_limits: {primary/secondary: {used_percent, window_minutes, reset_at}}, credits: {has_credits, unlimited, balance}, ... }` with the guard `if event.kind != "codex.rate_limits"`. These become `ResponseEvent::RateLimits(snapshot)` (sent from `codex-rs/codex-api/src/sse/responses.rs:80` and the websocket endpoint), exposed to clients as `EventMsg` "rate_limits" (`otel/src/events/session_telemetry.rs:1414`), and the app-server protocol serializes the same snapshot as `AccountRateLimitsUpdatedNotification { rate_limits: RateLimitSnapshot }` with `RateLimitWindow { used_percent: i32, window_duration_mins, resets_at }` (`app-server-protocol/src/protocol/v2/account.rs:752-760`). The fields are `used_percent` (note: used, not remaining), `window_minutes`/`window_duration_mins`, `resets_at`/`reset_at` (epoch seconds). This is the ChatGPT/Codex account stream, not the plain OpenAI API-key path.

**5 — Requesty.** The official docs llms index confirms a management API surface: "Get API Key Usage — GET — usage statistics for an API key" and "Get Organization Usage — GET — aggregated usage statistics for your organization", plus a Spend Limits feature ("Set budget caps per API key or project"), and billing is a prepaid USD balance. I did not open each usage-endpoint page to extract field names in this pass, so beyond "usage stats per key/org exist", anything else (including whether results expose a *remaining* budget rather than consumed usage) is could-not-verify.

**6 — opencode Go / Zen.** The Go subscription page (`https://opencode.ai/console/go`) is reachable but renders as an empty SPA shell for non-browser fetchers; per the "failures are data" rule its quota promises are could-not-verify. The models/Zen doc page (https://opencode.ai/docs/zen, served as the Console "Models" document) documents **no usage, quota, credits, or balance API at all** — no `/usage`, no limits endpoint, no headers. The observed runtime errors ("Go usage limit exceeded" with a wallet label; Zen free tier "Rate limit exceeded" / 403 `FreeTierError`) are **not** backed by any official documented quota-read surface. Verdict: **no official usage/quota API is documented for either.**

## Section A — scripted judge for `opencode/deepseek-v4.1-flash-free`

Official docs (https://opencode.ai/docs/zen, Console "Models" page) **do** document a direct API: "You can also access the models directly through the following API endpoints" — every free model including `deepseek-v4.1-flash-free` is listed with endpoint `https://opencode.ai/inference/openai/v1/chat/completions` (OpenAI-compatible, `@ai-sdk/openai-compatible`), plus `curl https://opencode.ai/inference/v1/models` for the model list, authenticated with an OpenCode Console API key. The legacy `https://opencode.ai/zen/v1` base URL observed to fail with 403 FreeTierError is **not** documented anywhere; the documented inference host is `opencode.ai/inference/...`.

Important caveat: the doc's pricing table lists the free models at "Free", with no documented rate-limit numbers — and the observed 403 FreeTierError shows tier restrictions exist behind the scenes without official documentation.

**Recommendation (verified 2026-10-18).** Calling the free model over direct HTTP does NOT work: from an ephemeral sandbox with a Zen API key, `POST https://opencode.ai/inference/openai/v1/chat/completions` (the documented host) AND `POST https://opencode.ai/zen/v1/chat/completions` both return `403 FreeTierError` ("free tier can only be used from within OpenCode"). Only `GET https://opencode.ai/inference/v1/models` answers 200 with the key. Therefore:
1. The judge for `opencode/deepseek-v4.1-flash-free` MUST go through an opencode session/CLI: `opencode run -m opencode/deepseek-v4.1-flash-free "<judge prompt>"` (docs: https://opencode.ai/docs/cli.md, `--model`/`-m`). No direct HTTP for free models.
2. A paid (non-`-free`) model id could probably use the direct endpoint, but that was not tested; mark it could-not-verify.
