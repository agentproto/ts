Account slots: a `profileRef` may name a slot, `slot:claude-primary`, resolved through the new `accountSlots` map in config.json (slot name -> real auth profile id, settable with `config_set accountSlots.<slot>`). One resolver, `resolveProfileRef`, is used at spawn (before host auth resolution, so a box receives the resolved credential), at restart, and when a `turnRetry.fallback` fires (the slot is kept in `fallbackBase` and resolved late, so a swap made while the session lives is followed). An unknown slot, or one naming a missing or disabled profile, is an explicit error (`account_slot_unresolved`), never a fallback. Sessions record the real profile in `accessProfile` and the requested slot in the new `accessSlot` field, recomputed at each restart. Slots are also accepted by `profileRefs` / `delegateProfileRefs`, `app_run`, cron agent actions, `decision_*` escalation targets, `session_continue_fresh`, `session_migrate`, `sandbox_exec.envProfiles`, workflow agent steps and harness presets; `llm_endpoint_set_upstream_link` refuses them explicitly. New MCP tools `account_slots_list` / `account_slots_swap` and CLI `agentproto accounts slots|swap <family> [--move-alive] [--dry-run]`; `--move-alive` restarts only alive sessions. `agentproto sessions switch-profile` now moves only alive sessions by default; `--include-dead` restores the old behaviour.
