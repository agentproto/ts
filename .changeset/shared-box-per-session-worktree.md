Per-session git worktrees on a shared sandbox box (AIP-36 follow-up). A spawn that attaches to a box other sessions may be using (`sandbox.reuse`) no longer re-checks out the shared per-workspace clone — which switched the branch out from under the other sessions and mixed their uncommitted files. Instead it keeps the `<home>/<workspaceSlug>` clone as the shared base and gives the session its own git worktree at `<home>/.worktrees/<workspaceSlug>/<slug>` (`wt/<slug>` cut from `baseRef`, or from `origin/<branch>` when a previous box pushed the work), with kindred branch precedence to the fresh-box checkout. Concurrent `git fetch` / `worktree add` on the shared clone serialize on a `flock` inside the box (`<home>/.worktrees/<workspaceSlug>.lock`); the base clone's own checkout is detached-never-re-pointed. All per-session paths (delivery/checkpoint, restore, cwd resolution, branch learning, teardown) now target the session's worktree. On detach from a still-shared box the session's worktree is removed through the box's exec — but only when it is clean and its branch is fully pushed; any leftover work keeps the worktree and logs a notice. A session alone on a fresh box keeps the exact previous checkout behaviour (no worktree layering, no lock, byte-identical commands).
