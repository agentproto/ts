Fix `events.jsonl` (and the `GET /sessions/:id/events` endpoint / `agent_export` markdown it feeds) stripping every newline out of `text-delta` and `thought` records. `transcript-writer.ts`'s `recordEvent` coalesced streamed chunks by splitting on `\r?\n` to find complete lines, then persisted each split fragment without reappending the terminator it had just consumed — so a blank (paragraph-break) line was stored as `""` instead of `"\n"`, and any consumer concatenating the raw `text` fields got the agent's markdown back as one run-on paragraph. The print-arm's own `StreamEvent` emission was already lossless (confirmed by a new round-trip test); the loss happened one layer downstream, in the daemon's persisted transcript capture. Reappend the terminator to each split line so the on-disk record is byte-for-byte reconstructable, and simplify `transcript-export.ts`'s reassembly to match (it no longer needs to guess a trailing `\n` back in from the `partial` flag). The ring-buffer/`projectEvent` path (live terminal view) already stores one entry per line with the separator added back by its own renderer, so it needed no change.
