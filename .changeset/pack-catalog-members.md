AIP-64 catalog members. `pack/v1` gains `roles`, `personas` and `policies`, each an array of `{ path }` to a ROLE.md, PERSONA.md or POLICY.md; the identity comes from the member's own file (`name`, or `id` for a policy, which a listed policy must declare). The manifest schema is now strict at the top level and in every nested object, as the spec says, so an unknown key is a parse error, which is also what refuses an `operators`, `companies` or `offices` member (instances are never pack content). A catalog path that is absolute, has a `..` segment, ends with the wrong filename, or is declared twice (within a member or across `apps`) is refused with no I/O. `readPackCatalog(root)` reads and validates every declared member before anything is registered and names the invalid one; it opens only declared files. `InstalledCatalog` registers a validated pack: refuses an identity another installed pack or a host `reserved` catalog already provides with a typed `PackCatalogConflictError` (code `pack_member_conflict`, naming both sources), replaces a re-applied pack's own members, refuses a gated pack with its blockers, scopes a pack to the node it is attached to, and answers `ws://roles/<name>`, `role:<name>` (and the persona and policy spellings) without any fallback. Installing binds nothing. `@agentproto/pack` now depends on `@agentproto/role`, `@agentproto/persona` and `@agentproto/policy`; a pack that carried an unknown manifest key, which parsed before, is now refused.

`@agentproto/role` exports `InstalledRoleSource` (adapts an installed catalog to the `RoleSource` seam, so it fits `resolveOperator`'s injected `OperatorSources.roles`), `roleSourceChain` (nodes' sources first, catalog sources after, AIP-47) and `RoleUnresolvableError` (code `role_unresolvable`, with `ref`, `warnings`, `chain`), which `resolveRole` now throws instead of an untyped `Error` with the same message.

`@agentproto/role-catalog` ships as a pack: `pack/` holds a PACK.md whose `roles` are the 21 in-code entries, rendered by `scripts/render-pack.mjs` (`pnpm render:pack`) with a drift test; `roleCatalogPackRoot()` returns its path. Because `plugin` is still required in `pack/v1`, the pack declares `plugin.inline: true` with an empty `./skills/` directory rather than relaxing the rule. The in-code catalog and `builtinRoleSource()` are unchanged.
