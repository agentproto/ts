Offer the MCP `io.modelcontextprotocol/tasks` extension on the modern `/mcp` gateway, following AIP-78 TURN-TASK: one session turn is one task. For a client that declares the extension, `agent_start` (with a prompt) and `agent_prompt` answer with a `CreateTaskResult` whose `_meta["io.agentproto/turn-task"]` carries the real `sessionId` and the prompt ticket; `tasks/get`, `tasks/update` and `tasks/cancel` follow that ticket. The host reserves the ticket (and the session id of an `agent_start`) before the call runs and writes the ledger entry before the prompt reaches the session; the per-principal cap and the capability check run first, so a refused call leaves nothing behind. The task is bound to its prompt ticket (not a queue position) and to the principal that created it. The terminal state and a bounded, redacted `TurnResult` (`{ sessionId, text, truncated }`) are written when the turn ends; session end, session removal and host restart close the task per the AIP mapping. `tasks/cancel` removes a queued ticket, interrupts only its own in-flight turn (the session stays alive), is a no-op on an ended one, and is an error when the harness cannot cancel. The ledger is written atomically (fsync, rename, `0600`); `ttlMs` counts from the end of the task and a task that has not ended is never purged. New config: `mcp.tasksTools`, `mcp.tasksTtlMs`, `mcp.tasksMaxTtlMs`, `mcp.tasksMaxPerPrincipal`, `mcp.tasksResultMaxChars`. The session registry gains prompt tickets: `enqueuePrompt({ promptId })`, `onPromptTicket`, `promptTicketState`, `cancelPromptTicket`. Disable with `mcp.tasks: false`.
