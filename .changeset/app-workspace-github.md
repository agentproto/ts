An app's WORKSPACE.md can now back its workspace with git: an inline `storage: github` with `sync.mode: pull-push`, a `config.repo_url` on github.com and an absolute `config.mount_path` is cloned there (through `@agentproto/storage-github`'s `createGithubWorkspaceSync`) when the app's workspace is registered, and the clone becomes the app workspace path. The token comes from the env var(s) named in `auth.state.env` (default `GITHUB_TOKEN`, `GH_TOKEN`). The clone only happens into an empty or missing directory; an existing git checkout is accepted untouched, any other non-empty directory is refused, and every failure falls back to the app dir. After a seed clone the token header storage-github writes into `.git/config` is removed — later pulls/pushes re-inject auth per invocation — so no credential is left at rest in the workspace. `branch_policy`/`pr_policy` are validated against the AIP-35 enums and dropped when unknown. A repo whose default branch is not `main` fails the clone unless `base_branch` is declared (the failure is warned and falls back to the app dir).
